# 공수 산정 챗봇

브라우저에서 단독 실행 가능한 정적 공수 산정 도구입니다.  
챗봇 방식으로 정보를 입력받고, 입력값을 기준으로 공수 항목, WBS 초안, 메일 첨부용 문구를 생성합니다.

## 실행 및 배포

브라우저에서 아래 파일을 직접 열면 실행됩니다.

```text
C:\Antigravity_PJT\공수산정\effort-estimation\index.html
```

웹 서버에 배포할 때는 `effort-estimation` 폴더를 그대로 올리면 됩니다.

```text
/effort-estimation/
  index.html
  app.js
  styles.css
  RockPlace_CI.jpg
  RockPlace_CI_transparent.png
```

실행에 필수인 파일은 다음 4개입니다.

```text
index.html
app.js
styles.css
RockPlace_CI_transparent.png
```

외부 API, CDN, 서버 호출이 없으므로 인터넷이 차단된 환경에서도 사용할 수 있습니다. 단, 브라우저 보안 정책에 따라 클립보드 복사 기능은 제한될 수 있습니다.

## 화면 구성

화면은 3단계로 구성됩니다.

```text
작은 채팅창 입력 → 공수 산정 → 산출물 관리
```

### 작은 채팅창 입력

처음 실행하면 전체 업무 화면 대신 `Database 공수 산정` 채팅창만 표시됩니다.  
사용자는 작은 채팅창 안에서 필요한 산정 조건을 순서대로 입력합니다.

입력 요약 확인 후 `공수 산정 시작`을 누르면 산정 애니메이션이 표시되고, 이후 `공수 산정`, `산출물 관리` 화면이 열립니다.

마지막 질문 이후에는 바로 산정하지 않고 입력 요약을 먼저 보여줍니다.  
요약 화면에서 특정 번호를 선택하면 해당 항목만 다시 입력할 수 있으며, 전체 재입력도 가능합니다.

### 공수 산정

생성된 공수 항목, WBS 초안, 메일 문구를 수정하는 화면입니다.

공수 항목을 수정하면 WBS와 메일 초안이 함께 갱신됩니다.  
공수 항목의 `+` 버튼은 해당 그룹 또는 해당 행 위치에 새 항목을 추가합니다.

### 산출물 관리

최종 예상 공수, 메일 첨부용 문구, WBS 엑셀 저장 버튼을 제공합니다.

메일 문구는 우측 상단 복사 아이콘으로 클립보드에 복사할 수 있습니다.  
WBS는 `.xlsx` 파일로 저장됩니다.

## 입력 흐름

### 공통 입력

모든 작업은 고객사명과 작업 구분을 먼저 입력합니다.

작업 구분은 다음 4가지입니다.

```text
신규 구성
메이저 업그레이드
대개체
이기종 마이그레이션
```

`신규 구성`, `메이저 업그레이드`, `대개체`는 제품과 구성방법을 선택합니다.

지원 제품과 구성방법은 다음과 같습니다.

| 제품 | 구성방법 |
| --- | --- |
| PostgreSQL | Single, HA(공유 스토리지), HA(Replication), HA + Auto Failover |
| MongoDB | Single, ReplicaSet, Shard Cluster |
| MySQL | Single, HA(공유 스토리지), HA(Replication), HA + Auto Failover, Cluster |
| MariaDB | Single, HA(공유 스토리지), HA(Replication), HA + Auto Failover, Cluster |
| Redis | Single, Sentinel, Cluster |

환경은 `DEV`, `STG`, `PRD` 중 체크박스로 선택하며, 선택과 동시에 각 환경의 대수를 입력합니다. 선택된 환경만 산정에 반영됩니다.

### 메이저 업그레이드 입력

메이저 업그레이드는 업그레이드 방식을 추가로 선택합니다.

```text
동일 서버 In-place
신규 서버 구성 후 교체
```

현재 버전과 목표 버전은 제품명을 포함해 질문합니다.

```text
PostgreSQL의 현재 버전을 입력해 주세요. 예) 9.4
PostgreSQL의 목표 버전을 입력해 주세요. 예) 11.4
```

버전은 숫자와 점만 허용합니다.

허용 예:

```text
9.4
11.4
6.0.14
16
```

허용하지 않는 예:

```text
MongoDB 4.4
PostgreSQL 9.7
임의 텍스트
```

### 이기종 마이그레이션 입력

이기종 마이그레이션은 제품/구성방법 대신 Source DB와 Target DB를 선택합니다.

Source DB:

```text
Oracle, PostgreSQL, MySQL, MariaDB, MongoDB, 기타
```

Target DB:

```text
PostgreSQL, EPAS, MySQL, MariaDB, MongoDB, 기타
```

추가로 다음 정보를 입력합니다.

| 항목 | 용도 |
| --- | --- |
| 환경/대수 | DEV/STG/PRD별 대상 대수 산정 |
| 데이터 규모 | CDC 또는 테스트 데이터 마이그레이션 공수 가중치 계산 |
| Object 수 | Table, Index, View, Procedure, Function, Package, LOB, Trigger 수 입력 |
| 다운타임 가능 여부 | CDC 사용 여부 판단 |
| CDC 필요 여부 | CDC 사용 여부 판단 |
| 테스트 마이그레이션 회수 | 입력 요약에 표시되는 참고값 |
| APP 테스트 지원 | PRD 단위/통합 테스트 지원 공수 반영 |
| SQL 변경 지원 | View/Procedure/Function/Package/Trigger 변경 지원 공수 반영 |
| 오픈 지원 | PRD 오픈 지원 공수 반영 |

데이터 규모는 테라 단위 숫자로만 입력합니다.

```text
0.03  = 30GB
1.2   = 1.2TB
5     = 5TB
```

## 검증 로직

입력값은 질문 타입별로 검증됩니다.

| 질문 타입 | 검증 |
| --- | --- |
| 선택형 | 현재 질문에 표시된 선택지만 허용 |
| 환경/대수 | 최소 1개 환경 선택 필요 |
| 숫자형 | 0 이상 숫자만 허용 |
| 버전 | 숫자와 점만 허용 |
| Object 수 | 각 항목을 0 이상 숫자로 입력 |

이전 질문의 버튼을 뒤늦게 눌러도 현재 질문이 아니면 반영되지 않습니다.

## 공수 산정 로직

공수는 `state.answers`에 저장된 입력값을 기준으로 `state.estimates` 배열에 생성됩니다.  
각 공수 항목은 다음 구조를 가집니다.

```js
{
  phase: "DEV 신규 구성",
  task: "엔진 설치 및 파라미터 세팅",
  days: 1,
  note: ""
}
```

환경 대수가 있는 경우 기본 공수에 대수를 곱합니다.

```text
항목 공수 = 기본 M/D x 환경 대수
```

### 신규 구성

제품과 구성방법에 따라 기본 작업을 생성합니다.

공통 예:

| 구성방법 | 기본 작업 |
| --- | --- |
| Single | 엔진 설치 및 파라미터 세팅 |
| HA(공유 스토리지) | 엔진 설치 및 파라미터 세팅, Failover 테스트 지원 |
| HA(Replication) | 엔진 설치 및 파라미터 세팅, Replication 구성 및 연동 확인 |
| HA + Auto Failover | 엔진 설치, Replication 구성, AutoFailover 세팅, AutoFailover 테스트 지원 |
| Cluster | 엔진 설치, Cluster 구성, AutoFailover 세팅, AutoFailover 테스트 지원 |

제품별 예외:

| 제품 | 예외 |
| --- | --- |
| MongoDB | Single, ReplicaSet, Shard Cluster별 작업이 별도 정의됨 |
| Redis | Single, Sentinel, Cluster별 작업이 별도 정의됨 |

APP 테스트 지원이 `예`이면 환경별 고객 응대 공수가 추가됩니다.  
모니터링이 `예`이면 환경별 모니터링 공수가 추가됩니다.

### 대개체

대개체는 신규 구성 작업을 기반으로 합니다.

차이점:

```text
엔진 설치 → 신규 서버에 엔진 설치
```

데이터 이관이 포함되면 다음 항목이 추가됩니다.

| 조건 | 추가 작업 |
| --- | --- |
| HA(Replication) | 데이터 마이그레이션 및 Replication 재구성 |
| 그 외 | 데이터 마이그레이션 |

환경별 후속 작업:

| 환경 | 후속 작업 |
| --- | --- |
| DEV | 고객 Application 테스트 문의 응대 |
| STG/PRD | 이관 후 모니터링 |

APP 테스트 지원 또는 모니터링을 `아니오`로 선택하면 해당 항목은 제거됩니다.

### 메이저 업그레이드

메이저 업그레이드는 업그레이드 방식에 따라 다르게 산정합니다.

#### 동일 서버 In-place

PostgreSQL/MySQL/MariaDB 계열은 다음 작업을 기준으로 합니다.

```text
AS-IS 구성 상태 확인
설치 파일 업로드 및 신규 엔진 설치
Application / DB 종료
Data Directory 복사
Major 업그레이드 수행
DB / Application 기동 및 서비스 체크
모니터링
```

MongoDB/Redis는 롤링 업그레이드 또는 엔진 교체 작업 중심으로 산정합니다.

#### 신규 서버 구성 후 교체

대개체 작업을 기반으로 하되 Major Upgrade 문구와 버전 정보를 반영합니다.

버전 표기는 다음처럼 생성됩니다.

```text
9.4 → 11.4
```

### 이기종 마이그레이션

이기종 마이그레이션은 단계형 공수로 생성됩니다.

기본 단계:

```text
1. AS-IS 분석 및 환경 설정
2. TO-BE 시스템 구축
3. 마이그레이션 준비
4. Object 전환 및 검증 준비
5. SQL 변경 지원
6. CDC 구성 또는 테스트 데이터 마이그레이션
7. 단위/통합 테스트 지원
8. 오픈 지원
9. 데이터 현행화
```

상세 기준:

| 단계 | 작업 | 기본 공수 |
| --- | --- | --- |
| AS-IS 분석 및 환경 설정 | AS-IS 시스템 분석 및 마이그레이션 환경 설정 | 5 M/D |
| TO-BE 시스템 구축 | 제품 설치 | 환경 대수 x 1 M/D |
| TO-BE 시스템 구축 | 파라미터 세팅 및 구성 | 환경 대수 x 1 M/D |
| 마이그레이션 준비 | 마이그레이션 도구 설치 및 환경 설정 | 환경 대수 x 3 M/D |
| Object 전환 및 검증 준비 | DDL 추출 및 Object 변환 | 환경 대수 x 3 M/D |
| Object 전환 및 검증 준비 | TO-BE Object 구성 | 환경 대수 x 2 M/D |
| SQL 변경 지원 | View/Procedure/Function/Package/Trigger 변경 지원 | 대상 객체 수 x 1 M/D, 최소 1 M/D |
| CDC 구성 | 초기 적재 및 데이터 동기화 진행 | 5 M/D x 데이터 규모 가중치 |
| 테스트 데이터 마이그레이션 | N차 테스트 데이터 마이그레이션 | 2 M/D x 데이터 규모 가중치 |
| 단위/통합 테스트 지원 | PRD 단위/통합 테스트 지원 및 문의 응대, 모니터링 | 20 M/D |
| 오픈 지원 | PRD Cutover/검증/모니터링 | 5 M/D |
| 데이터 현행화 | DEV/STG Object 및 데이터 현행화 | 각 2 M/D |

CDC 사용 여부는 다음 조건으로 판단합니다.

```js
useCdc = cdcRequired === "예" || downtime === "불가능"
```

즉 CDC 필요가 `예`이거나 다운타임 확보가 `불가능`이면 CDC 구성 경로로 갑니다.  
그 외에는 테스트 데이터 마이그레이션 경로로 갑니다.

데이터 규모 가중치:

| 데이터 규모 | 가중치 |
| --- | --- |
| 1T 미만 | 1 |
| 1T 이상 5T 미만 | 1.5 |
| 5T 이상 | 2 |

예:

```text
CDC 초기 적재 5 M/D
· 0.5T → 5 M/D
· 2T   → 7.5 M/D
· 5T   → 10 M/D

테스트 데이터 마이그레이션 2 M/D
· 0.5T → 2 M/D
· 2T   → 3 M/D
· 5T   → 4 M/D
```

## WBS 생성 로직

WBS는 공수 항목을 기준으로 생성됩니다.

각 WBS 항목 구조:

```js
{
  phase: "1. DEV 신규 구성",
  activity: "엔진 설치 및 파라미터 세팅",
  start: "2026-05-06",
  end: "2026-05-06",
  duration: 1,
  owner: "락플레이스",
  output: "",
  note: ""
}
```

일정은 기준 시작일을 기준으로 순차 배치됩니다.

```text
시작일 = 이전 작업 완료일 다음 날
완료일 = 시작일 + 기간(일) - 1
```

기간은 공수 M/D를 올림 처리하여 날짜 계산에 사용합니다.

```js
duration = Math.ceil(days)
```

담당자는 기본값으로 `락플레이스`가 들어갑니다.  
산출물은 실제 값이 아니라 placeholder로 안내되며, 사용자가 필요한 경우 직접 입력합니다.

## WBS 엑셀 저장 로직

WBS 엑셀은 브라우저에서 직접 `.xlsx` 파일 구조를 생성합니다. 별도 서버나 라이브러리를 사용하지 않습니다.

파일명은 다음 형식입니다.

```text
고객사_제품_구성구분_날짜.xlsx
```

이기종 마이그레이션의 경우 제품 대신 Source/Target DB 정보가 반영됩니다.

엑셀 구성:

```text
1행: WBS 제목
2행: 헤더
이후: 그룹 행 + 상세 작업 행
```

컬럼:

```text
단계, Activities, 시작일, 완료일, 기간(일), 담당자, 산출물, 비고
```

일반 작업은 DEV/STG/PRD 환경 기준으로 그룹핑합니다.  
이기종 마이그레이션은 AS-IS 분석, TO-BE 시스템 구축, 마이그레이션 준비 등 단계 기준으로 그룹핑합니다.

## 메일 문구 생성 로직

메일 문구는 다음 블록으로 구성됩니다.

```text
인사말

[산정 요약]
[대상 구성] 또는 [마이그레이션 대상]
[상세 공수]

공수 조정 가능 안내 문구
마무리 인사
```

메일 문구의 글머리는 `·`를 사용합니다.

예:

```text
[산정 요약]
· 작업 구분: 대개체
· 총 예상 공수: 16 M/D

[대상 구성]
· 제품/구성: PostgreSQL / HA + Auto Failover
· 대상 환경/대수: DEV 1, PRD 1

[상세 공수]
DEV 대개체 (1대) - 소계 9 M/D
  · 신규 서버에 엔진 설치 및 파라미터 세팅: 1 M/D
  · Replication 구성 및 연동 확인: 1 M/D
```

공수 산정 화면에서 메일 문구를 직접 수정할 수 있으며, 산출물 관리 화면에서 복사 아이콘으로 클립보드에 복사할 수 있습니다.

## 초기화 및 롤백 기준

화면 우측 상단의 `신규 공수 산정` 버튼을 누르면 입력 답변, 공수 항목, WBS, 메일 문구가 초기화되고 작은 채팅창 입력 화면으로 돌아갑니다.

현재 UI/워크플로우 기준 커밋:

```text
eb03d0503a54bacb24045515dc798cc589b79ae4
```

해당 커밋은 현재 디자인 개선 작업 전 기준점으로, 필요 시 Git에서 이 지점으로 되돌릴 수 있습니다.
